Problem → Solution

Battlefield radio and headset audio is drowned in gunfire, artillery, rotor and engine noise. Classical filters assume stationary noise and distort speech that overlaps with it.

1 · Noisy Battlefield Audio

Gunfire, explosions, helicopters, armoured vehicle engines corrupting radio/phone speech.

2 · DHVANI Filter Box

3 · Clear Command Audio

Speech reaches the soldier's ear intact — no muted commands, no missed orders.

How It Connects — Drop-In Filter Box

DHVANI doesn't replace any existing device. It's a small box that sits inline between a headphone and whatever the soldier already talks through — walkie-talkie, phone, or radio.

[Soldier's Talking Device] → [DHVANI Box] → [Headphone / Ear]

Incoming voice hits the box first, gets filtered in real time, then reaches whichever device the soldier is using — clean. Outgoing voice (mic → radio) is filtered the same way, since the codec is full-duplex. No new system to learn: it plugs into what's already in the field.

Why ESP32-S3

Low power draw and compact size — built for a soldier-worn device. Processes each 16ms audio frame in ~1.8ms, an 8.8× real-time margin.

  • I2S MEMS microphone (calibrated) for input
  • Dual ADC-DAC codec — full-duplex, RX and TX paths both filtered
  • 3.7V Li-Ion battery power
  • 3-LED live status indicator system
  • USB-C for programming/charging

  • Real-time streaming pipeline — measured, not simulated
  • Live public demo — mic input, file upload, two-device Field Comms Relay

In Progress / Roadmap

  • BiLSTM currently an optional Experimental mode — retraining (40→100 epochs) improved hybrid SNR from -1.1dB to +4.1dB, gap actively closing
  • PESQ measurement — blocked by a Windows C++ build toolchain requirement, on the roadmap
  • Embedded hardware deployment — currently laptop/cloud only for the software pipeline; the ESP32-S3 box is a separate working hardware prototype
  • Field Comms Relay is currently send/receive (snapshot), not full continuous-duplex streaming

Roadmap

Mid-Term
